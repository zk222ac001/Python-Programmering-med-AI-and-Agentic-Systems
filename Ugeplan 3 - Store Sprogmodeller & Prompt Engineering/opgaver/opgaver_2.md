# 🧪 Classroom Exercise 2 – Role-Based Prompt Engineering

## 🎯 Learning Objective

The purpose of this exercise is to help students understand how assigning a specific **ROLE** changes the way an LLM responds.

Each group will receive a different professional role and construct a complete structured prompt.

Students will use the following prompt-engineering framework:

```text
ROLE
TASK
CONTEXT
REQUIREMENTS
OUTPUT FORMAT
```

# 📝 Student Task

Each group must construct a complete prompt using the following structure:

```text
ROLE:
...

TASK:
...

CONTEXT:
...

REQUIREMENTS:
...

OUTPUT FORMAT:
...
```

---

# ✅ Example Prompt Structure

For example, **Group A** could create:

```text
ROLE:
You are an experienced Python teacher.

TASK:
Teach Python functions.

CONTEXT:
The students are beginners who already understand
variables, if statements, and loops.

REQUIREMENTS:
Use simple language.
Explain what a function is.
Give one real-world analogy.
Provide two Python examples.
Explain each example step by step.
Give students one small exercise.

OUTPUT FORMAT:
1. Definition
2. Real-world analogy
3. Example 1
4. Explanation
5. Example 2
6. Explanation
7. Student exercise
```

---

# 🧪 Test the Prompt

After creating the prompt:

1. Copy your prompt.
2. Open an LLM such as ChatGPT, Gemini, Claude, or another available model.
3. Submit the prompt.
4. Read the generated response.
5. Evaluate the quality of the output.
6. Modify the prompt if necessary.
7. Test the improved version again.

---

# 🔍 Evaluate the LLM Response

Each group should evaluate the response using the following criteria:

| Criteria                                | Yes/No |
| --------------------------------------- | ------ |
| Did the AI follow the assigned role?    |        |
| Did it complete the correct task?       |        |
| Did it use the provided context?        |        |
| Did it follow all requirements?         |        |
| Did it use the requested output format? |        |
| Was the answer clear and useful?        |        |

---

# 💬 Group Discussion

After testing the prompt, discuss:

1. Did the assigned **ROLE** affect the answer?
2. Was the **TASK** clearly understood by the LLM?
3. Did adding **CONTEXT** improve the response?
4. Which **REQUIREMENTS** had the biggest impact?
5. Did the AI follow the requested **OUTPUT FORMAT**?
6. What happened when the prompt was changed?
7. How could the prompt be improved further?

# 🎤 Group Presentation

# 🧠 Prompt Engineering Framework

```text
ROLE
   ↓
TASK
   ↓
CONTEXT
   ↓
REQUIREMENTS
   ↓
OUTPUT FORMAT
   ↓
LLM RESPONSE
   ↓
EVALUATE
   ↓
IMPROVE PROMPT
```

---

# ⭐ Key Learning Point

Different roles can cause an LLM to approach the **same problem from different professional perspectives**.

A well-designed prompt should clearly specify:

> **Role + Task + Context + Requirements + Output Format**

The goal is not only to write a prompt once, but to:

> **Create → Test → Evaluate → Improve → Test Again**

This iterative process is an important part of effective **Prompt Engineering**.
